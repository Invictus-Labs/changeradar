# Changelog

All notable changes to ChangeRadar. The format follows Keep a Changelog; versions follow semantic versioning once a first release is cut. Nothing here has been released yet.

## [Unreleased] - 0.1.0 MVP

### Added

- Explicit, schema-versioned dependency manifests (schema version 1) with unique node ids, source provenance and atomic import: dangling edges, duplicates, secret-looking values and unsupported major versions are rejected whole.
- Impact assessment of a proposed manifest against an immutable baseline hash: direct and transitive consumers with ordered source-to-consumer paths and owners; cycles terminate and are reported; identical content gives identical hashes and sorted findings.
- Three distinct verdicts, `AFFECTED`, `NO_KNOWN_IMPACT` and `INCOMPLETE`. Unknown, stale, unverified, placeholder, ownerless or undeclared inputs force `INCOMPLETE`; `NO_KNOWN_IMPACT` always states its coverage limits and is never presented as safe.
- Optional read-only live contract checks with a strict egress allowlist, timeouts, retries and visible failures that never become passes.
- HTTP API (`/api/v1`), a job worker with leased jobs and restart recovery, transactional outbox events, idempotency keys, workspaces with viewer, operator and admin roles, revocable cookie sessions with CSRF protection.
- Web UI (React) with loading, empty, denied and failed states, a graph view of impact paths, and a self-contained static HTML report whose finding ids match the JSON export.
- Versioned, hash-verified evidence bundles: `export`, `verify-bundle` and `restore` into a clean installation, with truncated, edited and unsupported bundles refused and no partial state.
- Command line: `migrate`, `serve`, `worker`, `admin create`, `credential`, `export`, `verify-bundle`, `restore`, `retention`, `idempotency prune`, `demo` (synthetic, account-free) and `sample-manifests`.
- Packaging: npm package (`bin: changeradar`), `Dockerfile` on Node 22.12, `compose.yaml` with PostgreSQL 17 and loopback-only published ports, `.env.example` with placeholders only.
- Operations documentation, a synthetic smoke runbook with an automated fresh-directory harness (supplemental evidence), and the independent human drill sheet for AC-11.
- Local quality gate `scripts/verify-quality.sh` covering typecheck, build, server and web suites with enforced coverage, PostgreSQL 17, seeded mutation controls, schema drift, dependency licenses, hygiene, packaged and browser end-to-end runs.

### Changed after independent review (round 1)

The first independent review of the 0.1.0 candidate found defects that this section records. Each one has a regression test that fails on the reviewed revision and passes now (`docs/qa/review-round1-ledger.md`).

- **A consumer excluded by its declared fields no longer hides bad evidence.** A consumer that declares `fields` and is not affected by a field change used to be dropped before its edge was checked, so an unverified, stale or future dated edge behind that exclusion could still give `NO_KNOWN_IMPACT`. Its edge is now examined (INCOMPLETE).
- Requiredness changes reach consumers in both directions; version rules treat downgrades, major 0 minor bumps and prerelease changes as breaking (`docs/DOMAIN.md`).
- Output is bounded: findings, stored paths (first and last 12 hops), change id lists, reasons, unknowns and listed changes are capped, and reaching a cap is an explicit `FINDINGS_TRUNCATED` unknown, never a safe verdict. A 10,000 node chain no longer exhausts memory (migration `004_finding_bounds.sql`).
- A check named in `check_keys` that is disabled before the worker runs is an unknown (`CHECK_NOT_RUN`), not silently dropped; the checks of one run share a 10 minute budget.
- Secret detection and redaction were rewritten (linear time, sees through zero-width and fullwidth text, many more shapes: npm, GitLab, SendGrid, Twilio, Azure, cookies, bearer, URL user names, webhooks, OAuth, Hugging Face, `aws_secret_access_key`); node and edge views are redacted. It is best effort and now documented as such.
- Repeated JSON object keys (`schema_version`, `verified_at`, `owner`, `nodes`, escaped variants) are refused with `DUPLICATE_JSON_KEY` in manifests, API bodies and bundles (`BUNDLE_DUPLICATE_KEY`); nesting and container bombs are refused before parsing.
- Authentication, role checks and rate limiting run before a request body is read; a request timeout and connection cap exist; anonymous requests are limited per address; login throttling is per account and address.
- A database that becomes unreachable after startup answers 503 `NOT_READY` (was 500).
- A stored credential is only sent to the origin its check was configured for, also across cross-origin then same-origin redirect chains; every vetted address of a host is tried when a connection cannot be established.
- CLI: an interrupted one-shot command exits 130 or 143 (was 0); repeated, value-less and unknown flags are usage errors (64); exit codes 66, 70, 73 and 141 are documented; `admin revoke` ends a member's sessions; `version` prints the source commit; `serve` closes the database when the port is taken.
- Documents: the bundle verification claims now say integrity, not authenticity (a test pins the limit); the runbook defines its package variable, verifies a checksum, bounds its readiness loop and no longer hard codes the port; the human drill requires the final commit, a checksum, a source-commit check and a kept transcript; request schemas ship as `schemas/api-requests.json`.

- New reasons for `INCOMPLETE` that round 1 introduced and this list omitted: unknown `UNKNOWNS_TRUNCATED` and `EDGE_FIELD_NOT_IN_CONTRACT`, and coverage limit `LIVE_CHECKS_NOT_RUN` (a run with checks enabled that ran none).

### Changed after independent re-review (round 2)

Four independent reviewers re-examined round 1 (`docs/qa/review-round1-ledger.md`, "Re-review wave" lists every finding and what became of it).

- **Decision engine version 2.** `fields` on a `produces` edge no longer filters (a consumer of a derived contract could be silently dropped); a consumer edge whose declared fields are not in the contract (a typo, a stale name, a valid and an invalid name mixed) is treated as undeclared and reported as an `EDGE_FIELD_NOT_IN_CONTRACT` unknown for baseline edges too; moving into a prerelease (`1.2.3` to `1.3.0-alpha.1`) and any change of the patch at `0.0.x` are breaking. **Upgrade note:** assessments are stamped with `engine_version`; runs made by an older engine show "re-run required", and bundles from an older build are refused with `BUNDLE_ENGINE_VERSION` (`docs/OPERATIONS.md`, Upgrade). *Superseded in round 3: bundles from an OLDER build are accepted and their runs are marked stale; only a bundle from a NEWER build is refused.*
- Checks selected by changed node are resolved when the run is requested, so disabling one before the worker runs is a `CHECK_NOT_RUN` unknown, not silence.
- Evidence bundles: verification compares every re-derived finding field, the unknowns and the assessment detail (not only ids); `export` verifies its own bundle and fails rather than write one that cannot be restored; ids that pass import are never rewritten by redaction (a workspace with such an id could not restore its own export); restore brings contract checks back disabled and bounds free text; the bundle claims are stated as integrity, not authenticity, with what is and is not re-derived.
- Redaction: quoted values with escaped quotes, secrets glued to letters, digits, `%20` or literal `\n`, invisible characters (U+034F, U+3164, ...), PGP blocks and `Cookie` keys are caught; there are no scan windows; text above the scan cap is refused, not passed; benign ids such as `auth-service:v1.2.3` are no longer rejected; 422 details never repeat a submitted id or field name; snapshot summaries are redacted.
- CLI and server: every printed string is escaped; a pipe or device is refused as bundle input; standard input is capped at 64 KiB; `help` prints to stdout; `--__proto__` is an unknown flag; SIGINT and SIGTERM are honoured during a restore; shutdown closes connections of slow clients after 5 seconds; exports have their own per-user rate limit; every 503 carries `Retry-After`; the compose database restarts.
- Tests and tooling: the three `FINDINGS_TRUNCATED` triggers are each proven alone, a mutant now counts as killed only by a failing assertion (shared, unit-tested classifier), stale mutation instruments were repaired, and `prepack` rebuilds before it stamps the source commit.

### Changed after independent re-review (round 3)

Four independent reviewers re-examined round 2 (`docs/qa/review-round1-ledger.md`, "Round 3" lists every finding and what became of it).

- **Decision engine version 3.** A NEW requirement (a field added as required, or one that becomes required) reaches every consumer of the contract, including a consumer that declares other fields.
- **Exports keep working across decision-engine versions.** (One limit, stated in docs/OPERATIONS.md, Upgrade: a snapshot whose stored manifest the CURRENT validator rejects, because the validator was widened after the manifest was accepted, makes export, `verify-bundle` and `restore` refuse fail-closed, naming the snapshot, the locations and the rule and no value, until that manifest is imported again; the manifest download serves such a manifest redacted.) A workspace or run export that holds runs from an older decision engine succeeds (it used to fail, and the run bundle answered HTTP 500). Those runs are accepted on their hashes, listed as stale by `verify-bundle` and `restore`, and marked "Re-run required" in the run list, the run view, both exports and the UI. A run from a newer engine is still refused with `BUNDLE_ENGINE_VERSION`.
- **Restored checks can be re-armed.** POST `/contract-checks` with the same key replaces a disabled check (allowlist and secret rules still apply); an enabled key is still a 409. The restore message says so.
- **Bundles redact all free text.** Workspace name, revision, warnings, error text, unknowns, assessment detail, event notes, check definitions and results and the contract check definitions (required field names and alias included) are redacted at export, capped at restore, and `required_fields` names and `credential_alias` are scanned at creation. `GET /contract-checks` redacts identifiers.
- Redaction: a quoted credential key at any JSON depth, unterminated quoted values, bracket and name/value forms, gaps of up to 64 characters, control characters, credential words inside property names, and no matches of `sk-` or `hf_` inside ordinary words.
- Redaction cross-check: escaped-quote runs and key names have no fixed length limit, a value on the line after `key:` and the operators `=>` and `:=` are recognised, a property name that holds a secret hides its value, and redacting twice equals redacting once (documented limits in `docs/MANIFEST.md`).
- Server and CLI: numeric cursors are validated (400, never 500), a 422 `UNKNOWN_CHECK` no longer repeats the submitted keys, bundle downloads have their own budget, a bundle above the installation limit is a 413 `BUNDLE_TOO_LARGE` (default limit 64 MiB, was 250 MB: memory is about 40 times the bundle size for ordinary text and up to about 130 times for a bundle made of numbers or one-key objects (measured)), standard output is escaped like standard error.
- Tests and tooling: the export-restore test compares every field of every check, the field families of the bundle verification are each pinned, a mutant is killed only by a failing test whose failure is a genuine assertion (structural, read from the test report), and the AC-13 durability script publishes a fixed port, keeps its password off the command line and asserts the run is queued at the restart. The script is still not executed here.

### Changed after independent re-review (round 4)

Four independent reviewers re-examined round 3 (`docs/qa/review-round1-ledger.md`, "Round 4" lists every finding and what became of it).

- **`changeradar export` honours the bundle limit.** The CLI workspace export used to write a bundle that `verify-bundle` and `restore` of the same installation refuse. It now refuses with `BUNDLE_TOO_LARGE` (exit 2) and writes nothing; the limit is measured in bytes. `.env.example` and the API guide say 64 MiB (memory is about 40 times the bundle size for ordinary text and up to about 130 times for a bundle made of numbers or one-key objects (measured)).
- **A run from an older decision engine has no current assessment.** `assessment` is `null` in the run view, the run list and the JSON export, and the old verdict is `recorded_assessment` (a new optional member of the response schemas): a script that gates on `NO_KNOWN_IMPACT` can no longer accept it. The run page shows a "RE-RUN REQUIRED" banner, and the HTML export labels every count, coverage statement and list as the older engine's.
- **Redaction.** A name/value pair (either order, other keys between, a path-shaped or cookie name, tuples, argument vectors) is recognised in text at any JSON depth and in objects; a YAML value on the next line is recognised at any depth; one level of percent-encoding is decoded into a scanned copy; a credential property name is recognised as a whole lower-cased key; format characters (category Cf) are folded away; redaction repeats to a fixed point. Documented limits are listed in `docs/MANIFEST.md`.
- **Mutation controls.** All three harnesses are checked by one gate step (`mutation-instruments`, `npm run mutation:check`) before any mutation step, so an edit that breaks an instrument fails the gate at once. Three instruments that round-3 edits had broken are repaired; the end-to-end harness uses the same structural rule and a wall-clock cap; without a test report nothing is ever counted as killed.
- Cursors: a position, a timestamp and a UUID are validated strictly (400 `INVALID_CURSOR`), and a database data exception is a 400, never a 500. An edge that declares `fields: []` is reported at import (`EMPTY_FIELD_DECLARATION`); its rule is unchanged. A run stamped with an older engine in a bundle is still checked for version-independent consistency. The per-address limiter keys an IPv6 client by its /64 and evicts idle buckets. Restore caps every stored string. Logins, logouts, manifest downloads, run exports and bundle downloads are audited. `--workspace-id` and `--run` must be UUIDs. The durability script no longer uses `--rm` and waits for five consecutive ready samples.

### Changed after independent re-review (round 5)

Four independent reviewers re-examined round 4 (`docs/qa/review-round1-ledger.md`, "Round 5" lists every finding and what became of it).

- **A restored workspace exports again.** Every text the decision engine derives (unknown messages, finding reasons) is cut to 2,000 characters when it is created, the bound a restore keeps; before, an `EDGE_FIELD_NOT_IN_CONTRACT` message that named many long unknown fields was cut by a restore and every later export of the restored installation was refused (`BUNDLE_RUN_INCONSISTENT`). Bundles written by earlier builds verify when their recorded text matches the derivation by one of three readings (redacted then cut, cut then redacted, or masked equality: the visible fragments of the record stand in the derived text, literally and in order, and each marker hides a non-empty span); the third reading was added after an independent review found that a bundle written by 435731e or 201e614 with two credential-shaped ids in one message (`edge auth:issuer|consumes|token:service was never verified`, which those builds wrote as `edge auth:[REDACTED] was never verified`) failed `verify-bundle` and `restore`.
- **A run bundle of an older-engine run carries a marker.** A top-level `stale_runs` member (outside every hash, checked against the runs), the response header `x-changeradar-stale-runs` and a CLI export message say which exported runs hold a recorded verdict that is history. The run page qualifies every statement, count and heading of such a run as the older engine's, as the HTML export does.
- **Redaction.** Name/value pairs without JSON quoting and YAML lists of them, pairs with a number, array or object value, wider key spellings and name words, gaps of up to 600 characters with objects between the halves; YAML block scalars, `&anchor` and `!!str` properties, flow groups and comment lines after a credential key; `?=` `+=` `||=` `??=`, `-p=`, `ENV NAME value`, typed declarations, long flags with a secret last word, Python string prefixes; the text keyword list follows the object key list; property names are folded like text; characters decoded from `%XX` never end a value. Every remaining gap is listed and pinned in docs/MANIFEST.md ("Not covered"), including passphrases with spaces.
- **Restore.** A hash-consistent bundle whose values the database refuses (a timestamp that is not a date, a NUL character, an integer past its column, a check outside the table's range, a malformed finding id) is `BUNDLE_SCHEMA_INVALID` at verification (exit 2), any database data or constraint error during the write maps to the same code, and run event statuses are capped like every other text.
- **Rate limiter.** A bucket that has used its whole allowance is never evicted, and making room is constant time however many spent buckets stand in front.
- **Mutation controls.** The kill rule reads the matcher part of a failure (a custom label can no longer make a genuine kill look like a crash), treats a crashed child by its exit status (null, 1, 70, 134 to 143), counts Testing Library lookup failures and labelled Playwright expects as assertions, and ends a runner's process group with it; new web mutants cover the stale banner and headings; the tests read real captured vitest and Playwright text. The full mutation runs are a gate step and have not been executed.
- **Documents and checks.** The acceptance matrix test ids are resolved against the test files by a test; the public content scan is clean on the tree; `docs/OPERATIONS.md` no longer says imports are vetted.

### Changed after independent re-review (round 6)

Four independent reviewers re-examined round 5 (`docs/qa/review-round1-ledger.md`, "Round 6" lists every finding and what became of it).

- **Redaction aims to hide no less than the tree before (measured on generated corpora, not guaranteed).** A differential over generated texts with planted synthetic secrets found text that the earlier redactor hid and the round-5 one showed (a decoded line break before the next key, a block scalar cut at a quote, a short key whose value is another key). Each root cause is fixed and frozen in four fixtures and named tests; the same method found none against the round-5 reviewed revision over about nine million texts of its own generators. Independent generators of round 7 found a few more garbled multi-layer texts (a few per 100,000 to 200,000 in the garbled styles) that only an older tree's habit of swallowing the next key hid: they are a documented, pinned limit and an open owner decision (docs/MANIFEST.md), not a guarantee.
- **A derived text is cut after redaction, never before.** A text that redaction lengthens (`[REDACTED]` is longer than a short secret) is cut to the 2,000-character bound afterwards and never inside a marker, so an export, its verification, a restore and the next export agree.
- **Two more bundle refusals.** An object key longer than 2,000 characters and an unpaired surrogate anywhere in a bundle are `BUNDLE_SCHEMA_INVALID` at `verify-bundle` and at `restore`, instead of a database error in the middle of the write.
- **Manifests an earlier build accepted and the current validator rejects.** Export and `verify-bundle` keep refusing (`BUNDLE_SNAPSHOT_MISMATCH`), and the refusal now names the snapshot id, the JSON locations and the rule, never the value; the stored manifest download is served redacted with `x-changeradar-manifest-redacted` (the stored document hash) instead of verbatim. A sanitized, hash-bound export of such a snapshot is an open owner decision.
- **Mutation controls and rate limiter.** The kill rule no longer reads a count as an exit status, labelled Playwright expects and `.resolves` failures classify as assertions, and three surviving mutants are killed; the per-address limiter reads only a well-formed address as an address.
- **Documents.** The memory needed to restore a bundle is stated as about 40 times its size for ordinary text and up to about 130 times for a bundle of numbers or one-key objects wherever the 64 MiB cap is discussed.

### Changed after independent re-review (round 7)

Four independent reviewers re-examined round 6 (`docs/qa/review-round1-ledger.md`, "Round 7" lists every finding and what became of it). Nothing below is claimed as verified until the exact-head review of the final revision says so.

- **Redaction.**
  - Recognised now: a JSON escape or an HTML entity of an ASCII character (`=`, `'`, `&quot;`, `&#61;`), pre-signed `signature=` and `X-Goog-Signature=`, the plural parents `passwords:`, `tokens:`, `secrets:`, `:=` behind `dsn`, `sid`, `jwt`, `pin`, `otp` and the other spaced-colon names, the user part of `TOKEN:x-oauth-basic@host`, and a `#` word after a YAML property (`password: &a #S`).
  - Forms that start a line are recognised after a line break written as text (a backslash and an n): `sid`, `pw`, `pin`, `otp`, `--flag S`, `-p=S`, `ENV` and `ARG` lines, bare name/value pairs.
  - Two flags whose first quote is not closed are both hidden.
  - A value that opens with a brace or a parenthesis and is glued to more text behind the closing character (`password={}S`, `token:{a}S`, `password=(ab3)S`, and a random password that starts so) is hidden with that text, like the square-bracket group since round 6 (a cross-check against a random-password generator, ruled P1; the tail was readable in every earlier tree). A delimiter right behind the group still ends the value.
  - The validator's check of a low-confidence span (`detectSecretKinds`, `containsSecret`) was quadratic on a repeated `-p=`; it is one remembered pass now, and the command-form readers count their steps against the work budget.
  - `redactSecrets(redactSecrets(x))` is the same as `redactSecrets(x)` on the generated corpora (the pass bound is 32 instead of 4); a chain of more than about 15 repeats of an encoded line break and bracket behind a header value is hidden whole by a second call, not the first (documented, pinned).
- **Linear time and a work budget.** Five families of text that were quadratic (the run after `!` or `&`, the value-first pair scan, a `#` comment in a gap, the comment after a block header, a run of backslashes in the pair scan) are read once. Every scan has a work budget of 64 counted steps per character (plus 65,536): a call that spends it hides the whole text, never part of it. A resealed bundle carrying one hostile text no longer stalls `verify-bundle` and `restore`, and a recorded text longer than 8,000 characters is refused at verification. What a scan remembers lives for one call (cleared at its start and its end, also after a throw). A static audit of every regular expression of `src/` (a quantified group with an unbounded inner quantifier, an alternation under an unbounded quantifier) finds none, and hostile runs of backslashes and percent escapes with a failing tail finish in milliseconds.
- **Bundles.** A run written by the round-5 base build, whose derived text was cut inside a short credential value, verifies, restores and exports again; two keys that differ only past the 2,000th character are refused at verification (`BUNDLE_SCHEMA_INVALID`), and a cut never separates a surrogate pair.
- **Mutation controls.** The kill rule reads a Playwright failure as an expectation only by its call line and block (an error a helper threw with `Expected:` and `Received:` lines is not one), a failed `.rejects` matcher is an assertion by vitest's own frame, a mutant whose module does not load is `INSTRUMENT_ERROR` before any test runs, and every result line of the harnesses records the text of its first failing assertion. Four survivors of the first full run were diagnosed as test gaps and killed (a service-level role check, a key over the cap that redaction shortens, the tail behind an embedded key, a bracket group glued to its word). The replay at revision 48fda4b, run from the live working tree and not from an archive (the evidence of the final revision is the gate run on an immutable archive): 289 of 289 main mutants and 21 of 21 web mutants killed (the 3 e2e mutants need a browser and were not part of it).
- **Events and audit.** The revision of an event is redacted when the envelope is written and again when it is served or pushed; audit rows are redacted again when served.
- **API.** The findings page has a `rerun_required` member (true for a run from an older engine); `fec0::/10`, `3fff::/20`, `2001:2::/48` and `2001:10::/28` are blocked for contract checks.
- **Documents.** The redaction promises say "measured on generated corpora, not guaranteed": independent generators found garbled multi-layer strings that an older tree hid and this one shows; they are pinned and an open owner decision.

### Changed after independent re-review (round 8)

- **Verbatim-tag lookahead bounded (security review, P2).** The search for the closing `>` of a verbatim tag (`!<tag:yaml.org,2002:str>`) ran to the end of the text for every `!<` start and was not counted: `password: !<` repeated cost 4 s of CPU at 1 MiB (quadratic). It is bounded to the longest tag (256 characters from the `!`) and counted against the work budget; a verbatim tag of up to that length reads exactly as before, and a text that holds `!<` very densely now spends the budget and is hidden whole (in about 0.1 s at 1 MiB). Mutants 348 became 351 (main 327).

- **Bundles and cuts.** An object key of six characters or more is redacted before the 2,000-character cap is applied, at `verify-bundle` and at `restore` (a repeated short unit such as `pwd: a|` grows 2.1 times, so a key of 994 characters was accepted and then refused by every later export); a cut of redacted text drops the partial word glued to the last marker, so the stored text is a fixed point of the redactor and a workspace can export its own fresh run; a word that starts with `!` is a YAML tag only when a blank, a line break or the end of the text follows it (`password: !]*9H_` was fully visible) and a verbatim tag `!<tag:yaml.org,2002:str>` is read to its closing bracket; a bracket or stray closer between the two quoted halves of a name/value pair is a documented limit (MANIFEST, pinned).
- **Second look at the same changes.** A glued `!` word is hidden from the `!` to the furthest of the word and the value read behind it, so `password: !'dx$awi` and `password: !{7eDk}` are hidden again (the first form of the rule left them readable; against the two earlier trees a differential of 600,000 generated strings over 19 shapes shows no text that they hid and this one shows, except the `!` tag followed by a text-written escape that the open owner list already names). A legacy bundle whose message the restore cut at 2,000 characters verifies, restores and exports again (a record of 1,991 to 2,000 characters is read as a masked prefix of the derivation). A resealed bundle can no longer blank a code, an id, an edge, a node id, a hash, the assessment or a whole text: the masked reading applies to `message`, `reason` and `description` only, and a marker must stand behind a credential-shaped word and its separator (`word:` or `word=`). What the masks still accept: a record whose last marker hides the rest of a message behind such a word (the form the earlier redactors wrote when a value ran to the end), so a truncation that ends at a credential-shaped word and a marker cannot be told from it.

### Fixed

- A `serve` start on a port that is already taken no longer leaves the worker polling and the process hanging.
- Two processes on the same embedded data directory (for example `serve` and `admin create`, or `serve` and `worker`) used to be accepted silently and could diverge; the second opener is now refused with the owner's process id, and a lock left by a crashed process is taken over.

### Known limits

Manifests are written by people and go stale; static declarations cannot establish runtime completeness; contract checking covers a required-field and type subset, not arbitrary schema compatibility. AC-11 (a fresh operator following the runbook) needs an independent human receipt and is pending. No live provider is used or claimed; contract checks were proven against local fixture servers.
